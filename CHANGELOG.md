# Changelog

## 0.1.0

Initial local implementation under the chosen Runalong name (`runalong`, with optional `ral` command alias).

- External Flutter VM Service frame capture alongside an existing automation command.
- Offline HTML, JSON, and Markdown reports with distinct automation/capture/budget states.
- Named configuration profiles, explicit budgets, and compatibility-aware baseline comparisons.
- Local stdio MCP tools and an optional evidence-driven analysis skill.
- Smooth/janky Flutter fixture with an unchanged integration-test journey and an external Maestro example.

Physical-device and runner-specific validation remain tracked in `doc/validation.md`. This version has not been published to pub.dev.
