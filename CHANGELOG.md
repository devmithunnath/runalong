# Changelog

## 0.1.0

Initial local implementation under the chosen Runalong name (`runalong`, with optional `ral` command alias).

- Journey explorer with shared frame, memory, CPU and widget/source selections; version-2 reports retain version-1 readers.
- Optional disabled-by-default `runalong_context` helper, named screen/operation scopes and unchanged-test reporter adapter.
- Separate measurement and diagnosis modes, bounded telemetry, clock calibration, per-group memory and conditional profiling-setting restoration.
- Stable-identity journey comparisons, reporting-only resource differences and bounded MCP journey/evidence tools.
- External Flutter VM Service frame capture alongside an existing automation command.
- Discover forwarded VM endpoints from verbose `flutter test` integration runs, including Flutter 3.29.
- Offline HTML, JSON, and Markdown reports with distinct automation/capture/budget states.
- Findings-first reports: explain slow rendering moments, suggest investigations, and open their exact frame ranges. Copy an evidence-linked investigation brief for a teammate or coding agent.
- Named configuration profiles, explicit budgets, and compatibility-aware baseline comparisons.
- Local stdio MCP tools and an optional evidence-driven analysis skill.
- Smooth/janky Flutter fixture with an unchanged integration-test journey and an external Maestro example.

Physical-device and runner-specific validation remain tracked in `doc/validation.md`. This version has not been published to pub.dev.
